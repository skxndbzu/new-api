# 最佳实践

## API Key 安全

- 服务端调用，不要在前端暴露 Key。
- 不要把 Key 提交到 Git 仓库。
- 不要把完整 Key 写入日志。
- 不同项目使用不同 Key。
- 发现泄露后立即删除或重置。

## 请求控制

- 合理设置 `max_tokens`，避免超长输出。
- 对输入长度做业务侧限制。
- 对 429 和 5xx 做有限次数重试。
- 使用指数退避，避免密集重试。
- 对长文本任务优先使用流式响应。

## 数据安全

- 日志不要保存敏感信息。
- 不要提交用户隐私数据，除非你已获得合法授权。
- 对用户输入做必要过滤和脱敏。
- 避免将机密、密码、证件号等内容发送给模型。

## 生产环境建议

- 为生产、测试、开发分别创建 Key。
- 设置调用上限或业务侧预算。
- 监控错误率、延迟和额度消耗。
- 对关键请求记录模型、时间、耗时、状态码和请求 ID。
- 为降级或切换模型预留策略。
